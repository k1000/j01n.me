# Spawn sprint integration runbook

Use this after a task-backed room has been created. The host coordinates merges; peers commit only on their own branches and do not push or merge. Generated outputs (`packages/helper/client/j01n.js`, `packages/helper/src/client-script.ts`, `apps/web/src/markdown-assets.ts`, `packages/skill/src/skill.ts`) belong to the integrator, not task `files[]`.

1. **Invite the owner and open the invitation.** Invite the owner to the room and open the resulting room link in the owner's browser. Once available, use `j01n invite-link --open` as host; until then use the normal owner invitation flow without copying the host's token or private key into a message. Confirm the owner appears in the room. Announce each integration stage in the room, including fetching GitLab, merging, deploying and pushing. Check task statuses, commits, contract evidence and file reservations; ask the relevant peer before touching a reserved path.
2. **Reconcile remotes before merging, deploying or pushing.** `git fetch gitlab` and `git fetch origin`; compare the intended integration branch with both remote heads (`git log --oneline --left-right HEAD...gitlab/<branch>` and the matching `origin/<branch>`). Inspect recent GitLab merge requests and any unexpected remote commits. Stop and reconcile instead of force-pushing or silently overwriting another actor's changes. Repeat fetch and comparison immediately before deploy/push if time has passed.
3. **Protect work in progress.** Check `git status --short` and `git worktree list` in every checkout involved. Never discard or reset another agent's work. If a shared checkout has uncommitted changes, prefer an isolated integration worktree from the intended commit. If this is impossible, get the owner of those changes to approve setting them aside; record their state, `git stash push -u -m 'pre-integration <date>'`, verify a clean working tree, and restore with `git stash apply` after integration, resolving conflicts with the owner. Do not drop the stash until restoration is confirmed.
4. **Merge only completed tasks.** Review each task diff, commit and evidence against its assigned scope; confirm reserved paths were released. Merge one branch at a time into the integration branch, inspecting conflicts and validating resulting behavior. Never merge generated artifacts from a peer as the authoritative build: regenerate them on the integration branch (`node scripts/generate-client-script.mjs` and `node scripts/generate-assets.mjs`) and commit any intended output changes.
5. **Check a clean snapshot.** Commit the integrated source and generated outputs, then verify `git status --porcelain` is empty. Run `pnpm check:contract` (or `npm run check:contract`) in that checkout. This checks typecheck, tests, both generated outputs and the production npm install path using `git archive HEAD` in a disposable directory. Run `node scripts/generate-client-script.mjs --check` and `node scripts/generate-assets.mjs --check` in the working tree as well; a clean archive alone cannot detect uncommitted generated drift. Stop on any failure.
6. **Deploy and verify live.** Deploy only the reviewed, clean commit using the project's deploy command (`pnpm deploy`). Verify the live helper with `node scripts/check-contract.mjs --smoke https://j01n.me` or `node scripts/smoke-helper.mjs https://j01n.me`; exercise the live MCP flow (create/join, list and mutate a task, inspect the result) and check the public page in a browser. Record the deployed commit and outcomes in the room. Do not treat unit tests alone as live verification.
7. **Push and tidy.** Fetch and compare both remotes once more; push the verified integration branch to `gitlab` and `origin` without force. Confirm both heads point to the deployed commit. Run `pi update` after pushing when updating the local Pi installation is part of the wave. Restore any approved stashes, ensure no work is stranded, then remove only worktrees whose branches are merged and whose `git status --porcelain` is empty. Never delete an unpushed branch, an untracked change or a worktree simply because it looks stale. Post the final report and close the sprint room only after the owner has had a chance to read it.
