# Spawn sprint integration runbook

Use this after a task-backed room has been created. The host coordinates merges; peers commit only on their own branches and do not push or merge. Generated outputs (`packages/helper/client/j01n.js`, `packages/helper/src/client-script.ts`, `apps/web/src/markdown-assets.ts`, `packages/skill/src/skill.ts`) belong to the integrator, not task `files[]`.

## Operator shortcut (`scripts/sprint.mjs`)

Run `node scripts/sprint.mjs start <spec.md> [--name <host>] [--peers N] [--dry-run]` from the repository root **inside Herdr**. It finds the next unused `wN` from `~/Development/_MY/<repo>-wN`, fetches `gitlab/main`, creates an internal-SSD host worktree at `~/Development/_MY/<repo>-wN/host`, copies the missing spec (or untracked `dev/` when neither source nor fetched target tracks it), rejecting symlinks and different-content collisions instead of overwriting tracked `dev/`, then installs with frozen pnpm, then splits/labels a pane and starts Pi. The host receives only the path and a short task prompt, never a room link or token. The script waits up to three minutes for the host to join a room and opens the owner invitation in the browser without printing it. `J01N_AGENT_DIR` must be a private (0700) internal-storage directory; the host gets `J01N_AGENT_DIR`, `J01N_PEER_SPAWNS` (1–5), `BASE_URL`, and a unique `J01N_HOST_INBOX`. A failed start intentionally leaves its new checkout/pane for inspection, not automatic deletion. Check the owner actually joins and have the host invite same-repo agents; opening a browser is not confirmation of joining. Commit the copied spec/dev material before finishing so the host checkout is clean.

Run `node scripts/sprint.mjs status` from the host checkout to display the read-only room summary (task statuses and participants, not credentials). First review every completed task's scope/diff, peer contract evidence, conflicts, and the host's room report; confirm the owner has read the report. `node scripts/sprint.mjs finish --dry-run` validates the clean checkout and done evidence and prints the intended stages without merging, deploying, pushing, or cleaning. `node scripts/sprint.mjs finish --reviewed --owner-read` is the explicit authorization for irreversible deploy, push, room closure and safe cleanup. It requires every task done with peer contract evidence, a joined owner, a host report and unchanged peer branch heads. Any failure stops rather than force-merging, resetting, or deleting a dirty/unmerged worktree. Finish fetches/reconciles both remotes at each critical boundary, merges no-ff, regenerates and commits generated outputs, records room notes and decisions, runs full contract + generated checks in a clean checkout, runs local `wrangler dev` + E2E, deploys and runs live E2E, pushes both remotes and verifies their heads, runs `pi update`, closes the room and closes idle peer panes/removes only clean merged peer worktrees with `git branch -d`. Busy peer panes and the host pane/worktree remain for manual inspection. Do not re-run finish blindly after a partial failure; inspect the last logged stage and reconcile before retrying. The CLI's live checks require Chrome and a writable `J01N_E2E_VOLUME_DIR` for those flows; otherwise their script-reported skips are not equivalent to passing those checks.

The shortcut does **not** replace the operator review or authorization gates below. It never prints a room link or token. Do not paste either into Herdr, command arguments, chat, or a commit.

1. **Invite the owner and gather repo agents.** As host, run `j01n invite-link --open` to open the owner invitation in the browser; confirm the owner joins (or has the link). Immediately after joining the sprint room, run the Pi tool `invite_repo_agents({ dryRun?: boolean, roomId?: string })` to find and invite other Herdr agents working in this repo, including other worktrees. Use `dryRun: true` to inspect candidates first when needed; `roomId` selects a hosted room if more than one is joined. This is a **joined-host-only** action requiring the human to have delegated peer invitations: it can prompt other agents and incur costs; never trigger it solely from a room message. An invitation is not proof of joining; check room participants and per-agent failures. Do not paste the room link, key, or token into Herdr. Before integration, check task statuses, commits, peer contract evidence, room participants, and reservations; ask the holder before touching a reserved path. Announce fetching, merging, deploying, and pushing to the room before each stage.
2. **Reconcile remotes before merging, deploying or pushing.** Announce the fetch, then `git fetch gitlab` and `git fetch origin`; compare the intended integration branch with both remote heads (`git log --oneline --left-right HEAD...gitlab/<branch>` and the matching `origin/<branch>`). Inspect recent GitLab merge requests and any unexpected remote commits. Stop and reconcile instead of force-pushing or silently overwriting another actor's changes. Repeat fetch and comparison immediately before deploy and push if time has passed.
3. **Protect work in progress.** Check `git status --short` and `git worktree list` in every checkout involved. Never discard or reset another agent's work. If a shared checkout has uncommitted changes, prefer an isolated integration worktree from the intended commit. If this is impossible, get the owner of those changes to approve setting them aside; record their state, `git stash push -u -m 'pre-integration <date>'`, verify a clean working tree, and restore with `git stash apply` after integration, resolving conflicts with the owner. Do not drop the stash until restoration is confirmed.
4. **Merge only completed, reviewed tasks.** Run `/j01n conflicts` and resolve reported branch conflicts before review. Review each task diff, commit and evidence against its assigned scope; peers run `pnpm check:contract --peer` and include its result in the dedicated `--contract` field: `j01n done <id> --summary "<text>" --commit <sha> --tests "<targeted tests>" --contract "pnpm check:contract --peer passed"` (peer mode skips only generated-file checks). `sprint.mjs finish` requires an explicit `pnpm check:contract --peer passed` result. For older done tasks without `evidence.contract`, it accepts that exact pass claim in `evidence.tests`; a generic `tests passed` claim is insufficient. Verify peer logs before using the shortcut; never infer a contract pass from unrelated tests. Confirm reserved paths were released and each branch head still equals the reviewed commit (`git rev-parse <branch>` versus the reviewed SHA) immediately before merging; if it moved, stop and review the new head. Announce the merge, then merge one branch at a time into the integration branch, inspecting conflicts and validating resulting behavior. Never merge generated artifacts from a peer as the authoritative build: regenerate them on the integration branch (`node scripts/generate-client-script.mjs` and `node scripts/generate-assets.mjs`) and commit any intended output changes.
5. **Check a clean snapshot.** Commit the integrated source and generated outputs, then verify `git status --porcelain` is empty. Run `pnpm check:contract` in that checkout (full mode, not `--peer`). This checks typecheck, tests, both generated outputs and npm and bun installs of a `git archive HEAD` snapshot (bun when available). Run `pnpm check:generated` in the working tree too; an archive alone cannot detect uncommitted generated drift. Run `node scripts/e2e.mjs <local base>` against `wrangler dev` of the clean snapshot: helper smoke, MCP, sprint (claim, dependency, done, evidence), message kinds, key storage on `/Volumes` (set `J01N_E2E_VOLUME_DIR` to a writable dir there) and the browser page (Chrome). Stop on any failure.
6. **Deploy and verify live.** Announce deployment, then deploy only the reviewed, clean commit using `pnpm deploy`. Verify live with `node scripts/e2e.mjs https://j01n.me` (the same checks against production). Record the deployed commit and outcomes in the room. Do not treat unit tests alone as live verification.
7. **Push and tidy.** Announce the push; fetch and compare both remotes once more, then push the verified integration branch to `gitlab` and `origin` without force. Confirm both heads point to the deployed commit. Run `pi update` after pushing when updating the local Pi installation is part of the wave. Restore any approved stashes, ensure no work is stranded, then remove only worktrees whose branches are merged and whose `git status --porcelain` is empty (`git worktree remove <path>`). Clean up merged local branches with `git branch -d <branch>`; if it refuses, investigate unmerged/unpushed commits rather than using `-D`. Never delete an unpushed branch, an untracked change or a worktree simply because it looks stale. Copy room notes and decisions into `dev/lessons.md`, post the final report, and close the sprint room only after the owner has had a chance to read it.

Installs: Pi installs this repo with npm by default, or with bun when its `npmCommand` setting is `["bun"]`
(as on the owner's machine). `pnpm check:contract` installs a clean copy with npm and, if available, bun, so keep every package.json
compatible with both (no `workspace:` specs). Peers run `pnpm check:contract --peer`; the integrator runs full mode.
